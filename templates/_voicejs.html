{# Voice input — the HYBRID mic (build 2026-11-18.32): a Google-style mic button inside every search-type field marked data-voice="1" — the home and platform link bars, video search, Video Toolkit, AI Tools, Script+Prompt and the Assistant (never name/email/report/review fields or textareas). ONE button, two engines, no language picker anywhere: 1. Web Speech API (as in .31): if the visitor speaks their phone/site language, words are typed LIVE while they speak — continuous + interim results, one alternative, the field updated on EVERY result event (no debounce) so text keeps up with speech; if recognition ends on its own mid-speech it restarts seamlessly and no text is lost. 2. AI transcription (new in .32): the same mic press ALSO records via MediaRecorder. On stop, the clip goes to POST /api/voice-transcribe (Gemini), which transcribes it in the language ACTUALLY spoken. The field is swapped to the AI text only when Web Speech produced no final text, or when the AI-detected language differs from the language Web Speech used — i.e. exactly the "spoke a different language than the phone's" case. Any failure (no mic for the recorder, network, server) silently keeps the live text. Text the visitor typed by hand before pressing the mic is never touched by either engine. Tapping the mic again stops; recordings cap at 30 seconds. Nothing is ever auto-submitted — the visitor presses the site's own Search / Download button as usual. For visitors who cannot type. Browsers with neither SpeechRecognition nor MediaRecorder+getUserMedia get NO button at all; browsers without SpeechRecognition but with recording get the mic in AI-only mode (graceful degradation throughout). Included right after _assistantjs.html on home + platform. Build 2026-11-18.35 (look only): the button face is Google's clean Material mic as an inline SVG in muted grey, red while listening — the owner found the 🎤 emoji looked wrong. Every behaviour below is exactly as in .32. #}
